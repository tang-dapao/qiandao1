## 拆分启动脚本 + dump 缓存优化（软件团队：工程师改 + QA 回归，47 测试全过）
用户需求：① 拆成"签到+反馈"和"看广告"两个启动脚本；② 做导航性能优化（dump 缓存）。
（背景：全流程 10 台一轮实测 ~40min，耗时大头是每次进出任务中心导航 ~90s——每次 find 都全量 dump。）

### 改动 A：拆分脚本
- main.py 新增 `--no-ad`（ad_times = 0 if args.no_ad else args.ad_times），docstring 更新。
- flow.py run_all：`target = ad_times if ad_times is not None else wf.ad_times_per_robot`（让显式 0 生效，
  不再被 `0 or X` 吞掉）；签到反馈循环后加 `if target <= 0: 跳过看广告轮转并 return`。
- 新增 `signin_feedback.bat`（--no-ad）和 `watch_ad.bat`（--ad-only），纯 ASCII 无 pause。

### 改动 B：dump 缓存（adb_ui.py）
- `__init__` 加 `_nodes_ttl=0.8` / `_nodes_cache` / `_nodes_include_desc` / `_nodes_ts`。
- `nodes()`：TTL 0.8s 内 + include_desc 相同 → 返回缓存；dump 失败返回 [] 不写缓存。
- 新增 `_invalidate_cache()`，在 tap/swipe_up/swipe_down/back 四个动作后调用。
- 关键设计：TTL 0.8s **必须 < wait_for 轮询 interval 1.0s**，否则 wait_for 会读到旧缓存。

### QA 结论（47/47 测试：14 adb_cache + 14 run_all_flags + 19 旧 test_flow_ocr_close 回归）
- A/B 均正确，无功能性 bug。新测试文件：test_adb_cache.py、test_run_all_flags.py。
- 失效完整性：生产路径无漏网（flow.py 唯一 subprocess 是 OCR 截图，只读不改屏）。
- 【LOW】`--no-ad --ad-only` 自相矛盾组合会"空跑"（每台白走 enter/exit），不报错；建议后续 main.py 加警告（非必需）。
- 【LOW】固有 0.8s 时间窗：页面自主变化（广告自动关/切帧）不经动作时缓存可能持旧快照 ≤0.8s，
  但所有动作→读间隔 ≥1.0s，实际不踩窗。
- 应测未测（真机）：缓存对 dump 次数真实下降、广告自动关瞬间 cache miss、两脚本真实时长对比。
